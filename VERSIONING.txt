AUTH PACKAGE VERSIONING RULES
==============================

Project Structure:
- V1 (root module): github.com/meikuraledutech/auth        → lives at repo root /
- V2 (submodule):   github.com/meikuraledutech/auth/v2     → lives at /v2

IMPORTANT Go Rule:
==================
Module paths ending with /v0 or /v1 are INVALID in Go's module system.
Only /v2 and above are accepted as major version suffixes.
- WRONG: module github.com/meikuraledutech/auth/v1   ← rejected by Go
- RIGHT: module github.com/meikuraledutech/auth       ← v1 is always the root

Git Tag Format:
===============

For v1 (root module):
  Format: vX.Y.Z
  Examples: v1.0.0, v1.1.0, v1.1.1, v1.2.0

For v2 submodule (/v2 directory):
  Format: v2.X.Y  (NO subdirectory prefix — Go resolves the right go.mod via import path)
  Examples: v2.0.0, v2.1.0, v2.1.1

Requirements:
=============

1. v1 has NO separate go.mod — it IS the root module (go.mod at repo root)
2. v2/ directory MUST have its own go.mod with: module github.com/meikuraledutech/auth/v2
3. v2 version tags must start with v2.x.x (major version must match path suffix)
4. Each submodule (v3+) follows the same pattern as v2

Example Git Commands:
=====================

Tag v1 (root module):
  git tag v1.2.0
  git push origin v1.2.0

Tag v2 submodule:
  git tag v2.0.0
  git push origin v2.0.0

Importing:
==========

V1 (root module):
  go get github.com/meikuraledutech/auth@v1.2.0
  import "github.com/meikuraledutech/auth"

V2 submodule:
  go get github.com/meikuraledutech/auth/v2@v2.0.0
  import "github.com/meikuraledutech/auth/v2"

⚠️ CRITICAL: go.mod replace Directive Rule:
==========================================

DO NOT include 'replace' directives in go.mod files that will be released/tagged!

❌ WRONG (in v2/examples/go.mod):
  replace github.com/meikuraledutech/auth/v2 => ../

  This breaks the Go module proxy because:
  1. The proxy downloads the code as a released module
  2. The replace directive references "../" which doesn't exist in the downloaded module
  3. Users get: "module X found (vX.Y.Z), but does not contain package Y"

✅ RIGHT (for released code):
  - Remove ALL replace directives before tagging
  - Ensure all require statements reference released versions
  - Use replace directives ONLY for LOCAL DEVELOPMENT, comment them out before release

  Example v2/examples/go.mod (for release):
  ```
  require (
    github.com/meikuraledutech/auth/v2 v2.0.0
  )
  // NO replace directive here!
  ```

  Example v2/examples/go.mod (for local development only):
  ```
  require (
    github.com/meikuraledutech/auth/v2 v2.0.0
  )
  replace github.com/meikuraledutech/auth/v2 => ../
  ```

Pre-Release Checklist:
======================
Before creating a version tag:
  ☐ Review all go.mod files (especially examples/)
  ☐ Remove/comment out ALL replace directives
  ☐ Update all version references to match the new tag
  ☐ Verify no local-only configurations are in the code
  ☐ Test the build without replace directives
  ☐ Then create and push the tag
  ☐ Allow 5-30 minutes for Go module proxy to index
